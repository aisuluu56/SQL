## Теория

Маршрут (route) — строка, показывающая текущее место в приложении: `/` для главной и `/details` для деталей. В Flet 1.0 для перехода можно асинхронно вызвать `await page.push_route("/details")`. Изменения маршрута обрабатываются `page.on_route_change`, а стэк `page.views` формируется заново в зависимости от `page.route`.

`ft.View(route="/...", controls=[...])` — экран с собственным набором элементов. Минимальный подход: очищать `page.views`, добавлять корневой View, а при другом route добавлять дочерний View. `page.on_view_pop` должен синхронизировать переход назад с верхним оставшимся View; для навигации предпочтительнее использовать методы page для маршрутов.

Избегайте смешения двух независимых источников состояния «текущий экран». Лучше всегда строить видимые Views только по `page.route`: тогда кнопка браузера «Назад», прямой URL и ссылки между экранами не расходятся.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
import flet as ft

def main(page: ft.Page):
    async def show_details(e):
        await page.push_route("/details")

    def route_changed(e=None):
        page.views.clear()
        page.views.append(ft.View(route="/", controls=[
            ft.Text("Главная", size=24),
            ft.Button("Подробнее", on_click=show_details),
        ]))
        if page.route == "/details":
            page.views.append(ft.View(route="/details", controls=[
                ft.AppBar(title=ft.Text("Детали")),
                ft.Text("Дополнительная информация"),
            ]))

    page.on_route_change = route_changed
    route_changed()

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.
