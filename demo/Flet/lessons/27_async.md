## Теория

Flet 1.0 использует единый цикл `asyncio`. Обработчик может быть `async def` и ждать неблокирующую операцию через `await`. В учебном примере задержку имитирует `asyncio.sleep`; это **не** блокирует остальные события, в отличие от `time.sleep`, который замораживает интерфейс.

Пока выполняется операция, покажите `ft.ProgressRing` или `ft.ProgressBar`, отключите кнопку от повторного нажатия (`disabled=True`), а после завершения восстановите управление. **Важно для Flet 1.0:** автоматическое обновление происходит в конце обработчика; `await` само по себе не отправляет промежуточные изменения на экран. Перед длительным ожиданием вызовите `page.update()` или `control.update()`, а при каждом шаге прогресса повторяйте обновление (либо используйте `yield` в асинхронном генераторе). Для ошибочных сценариев используйте `try/except/finally`: в `finally` спрячьте индикатор даже при ошибке.

Не все библиотеки асинхронные. Если операция CPU-bound или синхронная и долгая, потребуется отдельный поток/процесс либо специализированный механизм Flet; простое добавление `async` к функции не делает блокирующий код неблокирующим.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
import asyncio
import flet as ft

def main(page: ft.Page):
    indicator = ft.ProgressRing(visible=False)
    status = ft.Text("Готово к запуску")

    async def load(e):
        indicator.visible = True
        status.value = "Загрузка..."
        page.update()  # показать индикатор ДО ожидания
        await asyncio.sleep(1)
        indicator.visible = False
        status.value = "Данные загружены"

    page.add(ft.Button("Загрузить", on_click=load), indicator, status)

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.
