## Теория

Итоговая работа объединяет предыдущие темы: модель данных, UI-компоненты, формы, валидацию, фильтры, навигацию и работу с PostgreSQL. В отличие от маленьких упражнений, здесь важно проектирование: сначала запишите структуру сущностей, потом операции, затем экраны. Не начинайте с украшения кнопок.

Предлагаемая сущность `Ticket`: id (уникальный номер), title (проблема), room (кабинет), status (`Новая`, `В работе`, `Закрыта`), created_at (дата/время). Разделите код на независимые функции `load_tickets`, `insert_ticket`, `update_ticket_status`, `delete_ticket`, `render_list` и обработчики пользовательских действий. Не храните данные только в подписи карточки.

**Минимальная архитектура:** экран списка с поиском и фильтром, экран создания/редактирования и экран деталей; данные в PostgreSQL через Psycopg 3; переходы посредством `View`/route либо NavigationBar; подтверждение удаления через AlertDialog. Добавьте единый стиль, адаптивные карточки и пустое состояние.

**Готово**, когда можно создать заявку, увидеть её в списке, изменить статус, найти её поиском, удалить по подтверждению, перезапустить приложение без потери записей. Тестируйте особые случаи: пустое название, повторный клик, неизвестный id, недоступная БД, узкое окно, нулевое число результатов.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
# Миниатюрный пример разделения данных и представления:
from dataclasses import dataclass
import flet as ft

@dataclass
class Ticket:
    id: int
    title: str
    status: str = "Новая"

def ticket_view(ticket: Ticket):
    return ft.ListTile(title=ft.Text(ticket.title), subtitle=ft.Text(ticket.status))

def main(page: ft.Page):
    sample = [Ticket(1, "Не печатает принтер"), Ticket(2, "Не работает мышь", "В работе")]
    page.add(ft.Column(controls=[ticket_view(t) for t in sample]))

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.

## Минимальная схема данных

```sql
CREATE TABLE IF NOT EXISTS tickets (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    title TEXT NOT NULL CHECK (length(trim(title)) > 0),
    room VARCHAR(20) NOT NULL,
    status TEXT NOT NULL DEFAULT 'Новая'
        CHECK (status IN ('Новая', 'В работе', 'Закрыта')),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Схема приведена для понимания типов и ограничений; в практическом `.py` студент реализует её самостоятельно и пишет CRUD-запросы.
