# 11. Динамическое добавление и удаление элементов

> Уровень: **Компоненты** · Тема 11 из 28 · Цель: Создавать интерфейс по данным, а не вручную по одному элементу.

[← Оглавление](../README.md) · [Практическое задание](../tasks/11_dynamic.py) · [Официальная документация](https://flet.dev/docs/controls/column/)

## Теория

Списки Python удобно отображать как список controls. Например, `[ft.Text(name) for name in names]` создаёт столько элементов, сколько данных. Если список меняется, можно обновить контейнер: `column.controls = [...]` (и затем Flet перерисует изменённый UI).

Создавайте элементы через отдельную функцию, если внешний вид строк повторяется. У каждой записи должен быть стабильный идентификатор, особенно если надо удалять одну строку из нескольких одинаковых. Не используйте только текст названия как идентификатор: названия могут повторяться.

Для небольших списков `Column` подходит. Для десятков и сотен записей стоит выбирать `ListView`, чтобы не перегружать экран. В обработчиках старайтесь сначала изменить Python-данные, затем вызвать `render()`.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
import flet as ft

def main(page: ft.Page):
    topics = ["Python", "SQL"]
    items = ft.Column()

    def redraw():
        items.controls = [ft.Text(f"• {topic}") for topic in topics]

    def add_topic(e):
        topics.append("Новая тема")
        redraw()

    redraw()
    page.add(items, ft.Button("Добавить", on_click=add_topic))

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.
