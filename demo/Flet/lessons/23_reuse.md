## Теория

Когда одинаковая карточка повторяется 10 раз, не копируйте её код. Напишите функцию `build_card(item)` и возвращайте из неё обычный Flet control: `Container`, `Card`, `Row` и т. д. Функции сокращают дублирование, упрощают единое изменение стиля и позволяют тестировать форматирование данных отдельно от Flet.

Передавайте компонентам данные аргументами. Функция не должна без необходимости обращаться к глобальному `page` и менять состояние приложения. Если нужен обработчик, передайте callback извне: `build_card(item, on_open)` и используйте `on_click=lambda e: on_open(item["id"])`.

Разделяйте понятия: **данные** — словари/модели, **логика** — функции преобразования, **UI** — функции построения. Это важный шаг от маленьких прототипов к поддерживаемому приложению.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
import flet as ft

def build_badge(name: str, role: str):
    return ft.Container(padding=12, border_radius=12,
        bgcolor=ft.Colors.BLUE_50,
        content=ft.Column(controls=[ft.Text(name, weight=ft.FontWeight.BOLD), ft.Text(role)]))

def main(page: ft.Page):
    page.add(build_badge("Ольга", "Спикер"), build_badge("Илья", "Участник"))

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.
