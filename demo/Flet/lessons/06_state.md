## Теория

Состояние (state) — текущие данные интерфейса: число, выбор, список записей, активный экран. Состояние хранится в Python-переменных, а элементы Flet отображают его. При нажатии кнопки изменяются данные, затем показывается новое значение.

Если переменная определена в `main`, а вы присваиваете ей новое значение во внутренней функции, используйте `nonlocal`. Для простого счётчика подойдет число; для записей лучше список словарей или dataclass. Практика `render()` — собрать отображение в одном месте, чтобы не дублировать код обновления во всех обработчиках.

Не путайте **данные** и **представление**. Текст на экране не должен быть единственным местом хранения бизнес-данных: `int(label.value)` часто ведёт к хрупкому коду. Источником истины должна оставаться Python-модель.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
import flet as ft

def main(page: ft.Page):
    balance = 100
    label = ft.Text(size=26)

    def render():
        label.value = f"Баланс: {balance} баллов"

    def spend(e):
        nonlocal balance
        balance = max(0, balance - 10)
        render()

    render()
    page.add(label, ft.Button("Потратить 10", on_click=spend))

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.
