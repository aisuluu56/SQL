## Теория

**PostgreSQL** — полноценная серверная реляционная СУБД: база работает как отдельная служба, а Python-приложение подключается по сети. В отличие от файла JSON, данные хранятся в таблицах со столбцами, типами и ограничениями.

Для работы с PostgreSQL из Python используем **Psycopg 3** (`import psycopg`). Его установка описана в общем `requirements.txt`. Сначала поднимите сервер и создайте учебную базу: [инструкция по настройке](../db/README.md). Данные подключения хранятся в локальном `.env` (файл **не добавляется в Git**). Пример переменной:

```dotenv
DATABASE_URL=postgresql://flet_student:replace_with_local_password@localhost:5433/flet_academy
```

> Порт `5433` используется в комплектном Docker Compose, чтобы не конфликтовать с уже установленным PostgreSQL. При обычной локальной установке часто используется порт `5432`. Пароль и порт в `.env` должны соответствовать вашему серверу.

Краткий словарь SQL:

- `CREATE TABLE IF NOT EXISTS` — создать таблицу, только если её ещё нет.
- `GENERATED ALWAYS AS IDENTITY` — автоматически присваивать числовой первичный ключ.
- `INSERT ... RETURNING id` — добавить строку и получить её id.
- `SELECT ... ORDER BY` — прочитать и отсортировать строки.
- `DELETE FROM ... WHERE id = %s` — удалить конкретную строку.
- `UNIQUE`, `NOT NULL`, `CHECK` — ограничить допустимые данные ещё и на уровне БД.

**Защита от SQL-инъекций:** в Psycopg 3 используйте `%s` для значений, а сами значения передавайте отдельным аргументом `execute()`. Не составляйте SQL из введённого пользователем текста через f-строку. Запросы вида `cur.execute("... VALUES (%s)", (note,))` безопасно передают параметры, даже если текст содержит кавычки. Синтаксис `%s` используется и для чисел — это не подстановка строк силами Python.

**Транзакции:** `with psycopg.connect(...) as conn:` автоматически подтверждает изменения (`COMMIT`), если блок завершился без ошибки; иначе откатывает (`ROLLBACK`) и закрывает соединение. Для учебных операций можно открывать соединение на время одной короткой операции. Не передавайте пароль в исходных файлах и не публикуйте `.env`.

В Flet интерфейс отвечает за поля и кнопки, а функции работы с БД — за SQL. В обработчиках предусмотрите `try/except psycopg.Error`, чтобы при отключённом сервере приложение показывало понятную ошибку. Синхронные запросы подходят для первой учебной демонстрации; долгие запросы могут блокировать окно, поэтому в реальных приложениях используют фоновые задачи или асинхронный доступ.

## Разбор рабочего примера

Этот пример создаёт **заметки**, записывает новую заметку с параметром и показывает список. Практическое задание ниже будет про **кабинеты** с другой схемой и CRUD-логикой.

```python
import os
from pathlib import Path
import flet as ft
import psycopg
from dotenv import load_dotenv

load_dotenv(Path(__file__).resolve().parent / ".env")  # пример запускается из корня курса
DATABASE_URL = os.getenv("DATABASE_URL")


def list_notes():
    with psycopg.connect(DATABASE_URL, connect_timeout=5) as conn:
        with conn.cursor() as cur:
            cur.execute("""
                CREATE TABLE IF NOT EXISTS demo_notes (
                    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
                    body TEXT NOT NULL
                )
            """)
            cur.execute("INSERT INTO demo_notes (body) VALUES (%s)", ("Встреча в 10:00",))
            cur.execute("SELECT id, body FROM demo_notes ORDER BY id DESC LIMIT 10")
            return cur.fetchall()


def main(page: ft.Page):
    page.title = "Заметки из PostgreSQL"
    try:
        notes = list_notes()
    except (psycopg.Error, TypeError, ValueError) as exc:
        page.add(ft.Text(f"Ошибка подключения к базе: {exc}"))
        return
    page.add(ft.Column(controls=[ft.Text(f"{rid}: {body}") for rid, body in notes]))


ft.run(main)
```

Сохраните этот пример в **корень курса** как `demo_pg.py`, проверьте наличие `.env` и запустите `python demo_pg.py`. Каждый запуск добавляет одну демонстрационную заметку — это помогает увидеть, что данные переживают закрытие интерфейса. Таблица создаётся внутри выбранной базы `flet_academy`, а не в JSON-файле.

**Разбор по шагам:** `load_dotenv()` читает настройки; `psycopg.connect()` устанавливает соединение; `cur.execute()` выполняет SQL; `fetchall()` возвращает список кортежей; Flet превращает их в элементы интерфейса. `with` закрывает соединение без явного `conn.close()`.

## Типичная ошибка

В Psycopg 3 **не используйте `?` вместо `%s`** в параметризованных запросах. Не добавляйте кавычки вокруг `%s` в SQL: экранированием и типами занимается драйвер.
