## Теория

По мере роста приложения словари с магическими ключами становятся хрупкими: `student["garde"]` содержит опечатку, которую редактор может не заметить. `@dataclass` из стандартной библиотеки позволяет явно описать поля одной записи и создавать объекты с проверяемыми аннотациями типов.

Архитектура небольшого приложения может состоять из трёх частей: модель (сущности), сервис (операции над данными) и представление (Flet-интерфейс). Когда сложный расчёт находится в чистой функции, его можно проверить обычным assert без запуска окна.

Избегайте хранения `ft.Text` внутри модели: модель должна быть независима от Flet. Преобразование модели в строку для интерфейса делайте в функции отображения. Это облегчает переход от локального списка к файлам, PostgreSQL и API.

## Разбор рабочего примера

Ниже **законченный демонстрационный пример**. Его можно скопировать в отдельный файл и запустить; это **не решение** следующего задания.

```python
from dataclasses import dataclass
import flet as ft

@dataclass
class Product:
    title: str
    price: int
    quantity: int

def inventory_total(items: list[Product]) -> int:
    return sum(item.price * item.quantity for item in items)

def main(page: ft.Page):
    products = [Product("Кабель", 500, 4), Product("Роутер", 2000, 2)]
    page.add(ft.Text(f"Стоимость запасов: {inventory_total(products)} ₽"))

ft.run(main)
```

**Что проверить в примере:** прочитайте код сверху вниз, найдите место создания контролов, источник данных и (если есть) обработчик события. Измените одно значение и спрогнозируйте эффект **до** запуска.
